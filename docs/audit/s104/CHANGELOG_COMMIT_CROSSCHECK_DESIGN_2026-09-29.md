# 第 104 片设计：拿 `git log` 当第四源，把"整条条目缺席"判红

写于 2026-09-29，第 103 片认证进行中。本文只登记量具设计与**本轮现算**的开火证据，不改任何判据。

## 一、要闭的是什么

`tests/test_changelog_integrity.py` 那把尺的两道判决——`find_duplicate_blocks()` 与
`find_duplicate_entry_headings()`——都是**自洽型**的：前者问"同样的连续行有没有出现两次"，
后者问"三元组记号 `(v5.x, F-号, 第 N 片)` 在全文件唯一"。条目**少了一条**时，记号数与口径数
一起往下走，两边仍然相等、仍然唯一 ⇒ 结构上看不见缺席。今天一天之内撞了两次：

| 事故 | 落点提交 | 现场 |
| --- | --- | --- |
| 一（第 102 片） | 插 v5.63 那条时锚在 v5.62 标题行上，却没把标题行重贴 | v5.62 的正文留下、标题被吃；四道门禁全绿 |
| 二（第 103 片） | `629de86` 的 `git show --stat` 对 `CHANGELOG.md` 只有 `1 +` | **v5.64 整条没写**，`grep '5\.64'` 与 `第 103 片` 各自 0 命中；准备认证时才被 `git show --stat` 读出来 |

事故二比事故一更坏：事故一至少还有正文在，人读目录时会发现"这段没有标题"；事故二是什么都没留。

## 二、第四源：提交信息里的片号

判据不看 CHANGELOG 自己，而看另一张独立名册——仓库历史的主题行：

> 凡主题行里以 `s<NN>` 出现过的片号，`CHANGELOG.md` 必须有一行 `- **v…` 条目带着 `第 <NN> 片`。

方向只有这一边。条目侧比提交侧多出来的一律不算原告（今天实测：条目侧 101 个片号、
提交侧 52 个，差的 49 个是 `sNN` 主题约定之前那些轮次，反向判据会把它们全部误伤）。

## 三、本轮现算的开火证据（`git show <c>:CHANGELOG.md` 逐Blob 重放）

| Blob | 提交侧片号 | 条目侧片号 | 缺席 | 该不该开火 |
| --- | --- | --- | --- | --- |
| `beeb80f` | 50 | 99 | `[]` | 合规侧，不开火 ✓ |
| `35ef6fc` | 51 | 99 | `[101]` | 事故一现场，**开火** ✓ |
| `629de86` | 52 | 100 | `[103]` | 事故二现场，**开火** ✓ |
| `8f62f7e` | 52 | 100 | `[103]` | 同一现场的取证件提交，**开火** ✓ |
| `0a77ddd` | 52 | 101 | `[]` | 补写之后，合规侧 ✓ |

两档口径（严格 `^- \*\*v[0-9.]+ .*?F-[A-Za-z0-9-]+ 第 (\d+) 片` 与宽松 `^- \*\*v.*?第 (\d+) 片`）
在上面五个 Blob 上读数**逐条相同**（宽松多认 0 个）。落笔口径取**宽松**，理由是它少一种假红形状
（将来某条目不带 `F-` 号也认得到）；而"严格/宽松两把尺必须相等"这件事本身做成量具的一条自测控制——
一旦将来出现只被宽松认到的形状，两把尺就分叉，当场可见，而不是悄悄少认。
